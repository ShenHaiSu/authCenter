## 3. 业务码复用约定（本次**不新增**业务码）

三项功能一律复用《05 API 接口设计》§2 既有码表，不扩表、不改号：

| 场景 | HTTP | 业务码 | service 哨兵错误 |
|------|------|--------|------------------|
| 参数非法/越界 | 400 | 20001 `invalid_parameter` | `service.ErrInvalidParameter` |
| 校验失败（密码强度、范围） | 400 | 20003 `validation_failed` | `service.ErrPasswordTooWeak` 等 |
| 用户名冲突 | 409 | 20201 `name_conflict` | `store.ErrConflict` |
| 状态不允许（停用最后一个 owner、仍有密文时关加密） | 409 | 20202 `state_conflict` | 新增 `service.ErrStateConflict`（在 `respond.go: failService` 增一条 case 映射 409/20202） |
| 角色不足 | 403 | 20104 `forbidden` | 新增 `service.ErrForbidden`（映射 403/20104） |
| 资源不存在 | 404 | 20200 `not_found` | `store.ErrNotFound` |
| 账号停用 | 401 | 20102 `account_disabled` | `service.ErrAccountDisabled`（已存在） |

> 唯一允许的 `respond.go` 改动是**新增两个哨兵错误的 case**（`ErrForbidden`、`ErrStateConflict`），不新增码值。
> 对外认证接口（10001-10009）语义完全不变：解密失败等内部异常一律对外返回 `10004 key_not_found`，内部原因只进审计 detail。

## 4. 迁移与版本追踪规范（以《06》为唯一来源）

**权威文档**：`06-数据库迁移与版本追踪.md`。本节只保留 F-020 / F-021 实施时需要记住的三条约束，框架细节见《06》。

现状：`BackEnd/internal/database/database.go` 的 `migrations` 全部是 `CREATE TABLE IF NOT EXISTS` 追加式 DDL，**无版本记录**（未用 `PRAGMA user_version`）。
《06》确立：版本号权威来源 = `PRAGMA user_version`；迁移以 **step 注册表**执行（v1 基线表 / v2 `api_key_hash` / v3 `admin_user_role`）；**每 step 一个事务**，版本号与 DDL 同事务提交；`cur > target` 时**拒绝启动**（防旧二进制读新库）。

**F-020 / F-021 实施时必须遵守**：
1. 新增列一律走 `ensureColumn`（幂等 ALTER helper，实现见《06》配套的 `internal/database/migrate.go`），**不要**直接把 `ALTER TABLE` 写进 `migrations`。
2. 结构变更登记为**新的 step**（版本号只增不改，历史 step 禁止修改），DDL 与其小数据回填（如 F-020 的 owner 回填）写在**同一 step 同一事务**内。
3. 大数据量回填（如 F-021 的 `key_hash`）**不进启动路径**，改为 `Job` 后台任务（框架见《06》§4，任务状态键见 §1）。
4. 索引一律 `CREATE INDEX IF NOT EXISTS`（天然幂等）。

**`ensureColumn` 参考实现**（落地位置：`internal/database/migrate.go`，即《06》的配套文件）：

```go
// ensureColumn 幂等新增列：列已存在则直接返回 nil（迁移可重复执行）。
// PRAGMA table_info(<table>) 返回该表全部列定义，据此判断列是否存在。
func ensureColumn(db *sql.DB, table, column string) error {
	rows, err := db.Query("PRAGMA table_info(" + table + ")")
	if err != nil {
		return fmt.Errorf("读取 %s 表结构失败: %w", table, err)
	}
	defer rows.Close()
	for rows.Next() {
		var cid int
		var name, ctype string
		var notnull int
		var dflt any
		var pk int
		if err := rows.Scan(&cid, &name, &ctype, &notnull, &dflt, &pk); err != nil {
			return fmt.Errorf("扫描 %s 表结构失败: %w", table, err)
		}
		if name == column {
			return nil // 已存在
		}
	}
	if err := rows.Err(); err != nil {
		return err
	}
	if _, err := db.Exec(fmt.Sprintf("ALTER TABLE %s ADD COLUMN %s", table, column)); err != nil {
		return fmt.Errorf("为 %s 新增列 %s 失败: %w", table, column, err)
	}
	return nil
}
```

调用方式：不再往 `migrations` 里追加裸 DDL，而是在 `migrationSteps` 注册表中**新增一个 step**（版本号递增），step 内部调用 `ensureColumn` / `CREATE INDEX IF NOT EXISTS`，并把数据回填（若体量小）放在同一事务内。完整流程见《06》§3、§7。

**约束**：
- `ALTER TABLE ADD COLUMN` 的新列**必须有默认值或可空**（SQLite 不支持带非恒定默认的 ADD COLUMN），本设计所有新列均给常量默认或允许 NULL。
- 迁移失败 → 启动返回错误并退出（现有 `migrate` 已是此行为，勿改）。
- `PRAGMA user_version` 高于当前二进制支持的版本 → **拒绝启动**（见《06》§3.3）。

## 5. 备份与回滚（所有 schema 类改动的前置动作）

```bash
# 停止服务后备份（必须连同 WAL/SHM 一起拷，否则可能拿到不一致快照）
cp data/authcenter.db   data/authcenter.db.bak
[ -f data/authcenter.db-wal ] && cp data/authcenter.db-wal data/authcenter.db-wal.bak
[ -f data/authcenter.db-shm ] && cp data/authcenter.db-shm data/authcenter.db-shm.bak
```

回滚：停服务 → 覆盖回 `.bak` 三件套 → 启动。**回滚不需要重跑脚本**，因为新列对旧二进制是透明的（旧代码不会引用新列）。

## 7. 前端落地统一约定（三项共用）

- 新增视图一律沿用 `index.html` 内 `<section id="view-xxx">` + 侧边栏 `<a data-view="xxx">` + `app.js` 的 `VIEW_TITLES` / `VIEW_LOADERS` 三处接入（沿用 `newInterfaceDesign/03` §1 确立的标准）。
- **导航项按角色隐藏**（F-020 引入）：`app.js` 的 `init()` 里根据 `/admin/me` 返回的 `role` 决定 `#nav-admins` 是否 `display:none`；后端仍必须独立鉴权，前端隐藏只是体验。
- 样式**只允许追加**到 `base.css`，复用已有类：`card / card-title / form-group / form-control / form-hint / form-error / table / table-wrap / badge(+success|warning|danger|info|muted) / btn(+primary|danger|sm|link) / modal-* / toast / confirmAction / empty / loading / spinner / stat-card / stats-grid / toolbar / pagination / callout(+tip|warn) / key-value-box / key-warning`。
  确实需要新类时（如设置页的开关行），在 `base.css` 末尾新增一节并加注释标注所属设计文档编号。
- 破坏性操作（停用管理员、关闭加密、立即清理审计）必须走 `confirmAction()` 二次确认，文案要点明不可逆后果。
- 所有服务端返回的字符串进入 HTML 前一律 `escapeHtml()`。
