## 3. 里程碑划分（建议 M6.1 / M7 / M8 / M9）

```
M6.1 收尾（10 分钟级）   gofmt 修复 + .gitattributes eol + 补 Document 01 中 F-018 状态回写
   └── 前置项：不修则《08》§5 门禁「gofmt -l 无输出」持续不通过
步骤 2（基础设施：《06》）  step 注册表 + PRAGMA user_version + MaintenanceRunner + -migrate-only
   └── 先行合入的独立提交；自身无 DDL 变更（v1 基线包装），不影响任何现有行为
M7 = F-019 审计保留策略     纯 settings + 后台任务 + 1 个管理视图，无 schema 变更
M8 = F-021 密钥存储加密     迁移 step v2 + 密钥回填后台 job + 认证主路径改造
M9 = F-020 多管理员与 RBAC   迁移 step v3 + 会话归属修正 + 2 个管理视图 + 越权矩阵
```

排序理由：
- **步骤 2 先行**：《06》的迁移框架与维护任务框架是三份设计的共用底座，但只做框架 + v1 基线，不改任何现有行为，可独立评审合入。
- **F-019 先行**：无 schema 变更、无兼容性风险、闭环最短，可作为新里程碑的模板。
- **F-021 优先于 F-020**：安全收益直接、边界清晰；F-020 涉及会话归属与前端导航权限，改动面最大，放最后。
- **F-020 必须独立成里程碑**：它会修改 `middleware.go` 的用户解析方式（当前硬编码 `admin`），属于全局行为变更，需要完整的越权回归矩阵。
- **版本号按落地顺序分配**：M8 先于 M9，因此 F-021 的迁移 step 为 v2、F-020 的为 v3（见《06》§3.1）。

## 4. 三份设计共用的项目标准（务必遵守）

| 维度 | 硬性要求 | 依据 |
|------|----------|------|
| 语言/依赖 | 纯 Go 标准库为主，**禁止 cgo**；`CGO_ENABLED=0 go build ./...` 必须通过 | 需求红线 R1 / 文档 08 §5 |
| 分层 | `store` 只碰 SQL；`service` 承载业务规则与审计；`httpapi` 只做编解码与错误码映射 | 文档 04 §1 |
| 错误处理 | service 抛哨兵错误（`errors.New`）→ `failService` 统一映射；**本次三项均不新增业务码**，只复用 05 §2 既有码 | 文档 05 §2 |
| 审计 | 所有写操作必须写审计；**detail 严禁出现密钥/密码/主密钥明文** | 文档 06 §6 |
| 日志 | `slog` 结构化；后台任务错误只记日志不阻断主流程 | 文档 04 §6 |
| 时间 | 一律 UTC ISO8601（`database.FormatTime` / `NowUTC`） | 文档 03 §2 |
| 配置 | 运行期可变项走 `settings` 表；启动期固定项走 flag/env。**秘密只走 env，不入库** | 文档 04 §2 |
| 前端 | 原生三件套；多页面+视图切换；动态渲染一律 `escapeHtml()`；仅复用 `base.css` 已有组件类 | 前端架构 01/02 |
| 前端资源 | 全部本地化，**禁止任何外部 URL**；随 `go:embed` 与 Bundle 自动携带 | 需求红线 C5 |
| 格式 | `gofmt -l BackEnd` 必须无输出；`go vet ./...` 无告警；`go test ./...` 全绿 | 文档 08 §5 |
| 文档同步 | 每个里程碑结束需回写 `Documents/backEndArchitect/01/03/05/06` 与根 `README.md`，并出验收报告（对齐 M4/M5/M6 的 `09~13` 体例） | 项目既有标准 |

## 5. 全局风险与红线（三项共用）

| 风险 | 红线要求 |
|------|----------|
| 数据不可逆 | 任何 `ALTER TABLE` / 删除类操作必须先备份 `data/authcenter.db`（连同 `-wal`/`-shm`），并在文档中给出回滚步骤 |
| 启动自检 | 迁移或解密自检失败 → **退出并报错**，绝不带病启动（沿用 M1「启动自检失败即退出」约定） |
| 幂等 | 重复启动不产生副作用；所有 DDL 幂等（`CREATE TABLE IF NOT EXISTS` + 幂等 ALTER helper，见《05》§4）；大数据回填走后台 job，不阻塞启动 |
| 性能不回退 | 认证主路径 P99 预算 50ms、≥100 QPS 不变；F-021 需补加密态基准并对比 M6 基线（1.85ms/op） |
| 认证语义不变 | F-021 加密后，对外认证的**业务码语义一律不变**（解密失败对外仍按 10004 `key_not_found`，只在审计 detail 记内部原因） |
| 降级保护 | schema 版本（`PRAGMA user_version`）高于当前二进制支持的版本 → **拒绝启动**；详见《06》§3.3 |
