## 2. 实施顺序（建议）

1. **文档同步**：先更新 `frontEndArchitect/02` 的视图表格与验收清单（记录设计基线）；
2. **index.html + app.js**：先接入两个空视图（导航 + section + VIEW_LOADERS 占位函数），
   确保视图切换、会话守卫、标题切换即生效；
3. **guide.js**：按《01》§5 大纲填充七节静态内容，验证渲染与锚点；
4. **docs.js**：先定义 `DOC_SECTIONS` 数据（对照《02》§6 与 `attachments/AuthCenter-接入对接文档.md`），
   再实现双渲染器与下载；
5. **base.css**：补样式节，核对与现有变量体系一致；
6. **验证**：开发模式 `go run ./cmd/authcenter -web-dir ../FrontEnd` 手工验收 + 构建模式
   `build.ps1` 后内嵌验证（见 §4）。

## 3. 编码规范对照（沿用前端架构 01/02）

| 规范 | 本项目要求 | 两个新界面的落实 |
|------|-----------|------------------|
| 语言 | 原生 HTML5/CSS3/Vanilla JS | ✅ 无框架、无依赖 |
| 外部资源 | 禁止引用任何外部 URL（字体/图标/库） | ✅ 全部本地化 |
| XSS | 动态渲染一律 `escapeHtml()` | ✅ 教程/文档内容渲染统一转义 |
| 错误处理 | 三态（空/加载/错误）+ toast | ✅ 静态内容无加载态；异常走 `toastError` 兜底 |
| 视图约定 | `showView` + `VIEW_TITLES`/`VIEW_LOADERS` | ✅ 完全复用 |
| 语义化类名 | base.css 现有命名风格（kebab-case） | ✅ `.guide-toc`/`.code-block`/`.callout` |
| 注释规范 | 文件头注释 `/* js/xxx.js — 说明 */` + 关联文档编号 | ✅ 新文件头注明「新界面设计 01/02」 |

## 5. 风险与备注

| 项 | 说明 |
|----|------|
| 文档漂移 | 对接文档内容以「单源 `DOC_SECTIONS`」维护；后端接口变更（如 v2）时只需改一处数据 + 重跑验收 C 项 |
| 截图占位 | 教程页 `.guide-shot` 为占位；如需真实截图，在实施期补拍并替换（同样本地化存放） |
| MD 内容体积 | 预计 8-12KB，内嵌进二进制可忽略不计；`Blob` 下载无内存压力 |
| 浏览器兼容 | `Blob`/`URL.createObjectURL`/`a.download` 为现代浏览器标准能力；若需兼容旧内核可加 `navigator.msSaveBlob` 降级（P2） |
