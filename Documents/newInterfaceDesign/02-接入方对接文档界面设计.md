# 02 接入方对接文档界面设计

> 新界面设计 2/3 ｜ 界面二：其他项目接入认证后端的对接文档页 + Markdown 下载
> 定位：给真实项目的开发人员「直接拿去学习对接」的完整接口文档，支持一键下载 MD、脱离平台传递。

## 1. 设计目标与原则

- **目标**：页面内完整呈现「如何对接 AuthCenter 认证后端」：服务地址、认证接口的
  URL / 请求参数 / 请求体 / 响应体，以及每个字段的作用与意义、错误码、令牌、限流、
  各语言示例；并提供**下载按钮**，把页面内容对应的完整 Markdown 下载给开发人员。
- **原则**：
  - **单源同构（核心）**：页面渲染与 MD 下载共用**同一份结构化内容数据**，
    保证「页面上看到的 = 下载的 MD」一字不差，杜绝两份文档漂移；
  - **对接者视角**：内容按「我作为一个新项目的开发，要做什么」组织，
    从开户（管理员建项目/发密钥）→ 调用 → 解析结果 → 排错，全链路闭环；
  - **与实现严格一致**：所有接口字段、错误码、校验顺序、JWT claims 均逐条核对
    `BackEnd/internal/httpapi/*` 与 `service/*` 源码，文档 05 为准、源码兜底；
  - **零后端依赖**：同界面一，不调用任何 API；MD 由浏览器本地生成下载。

## 3. 单源内容模型（docs.js 数据设计）

对接文档体量较大（约 12 个小节、多张表格、多个代码块），设计为**结构化内容数据 + 双渲染器**：

```js
/* js/docs.js —— 内容数据（唯一事实源） */
const DOC_SECTIONS = [
  {
    id: 'overview', title: '一、概述与接入流程', level: 2,
    blocks: [
      { type: 'p', md: 'AuthCenter 是内部中心认证服务……' },
      { type: 'steps', md: ['1. 联系管理员创建项目并申请密钥', '2. ……'], items: [...] },
      { type: 'table', md: '| 字段 | 说明 |\n|---|------|', rows: [[...], ...] },
      { type: 'code', lang: 'bash', md: 'curl ...' },
      { type: 'note', md: '> 注意：……' },
    ],
  },
  // ...
];
```

| 块类型 | 页面渲染（HTML） | MD 渲染（下载） |
|--------|------------------|-----------------|
| `p` 段落 | `<p>`（escapeHtml） | 原样段落 |
| `steps` 有序列表 | `<ol class="guide-steps">` | `1. 2. 3.` |
| `table` 表格 | `<table class="table">` | GFM 表格（含表头分隔行） |
| `code` 代码块 | `<pre class="code-block"><code>`（escapeHtml） | 围栏代码块 ` ```lang ` |
| `note` 引用提示 | `<div class="callout callout-tip">` | GFM 引用 `> ` |
| `h3/h4` 小节 | 标题 | `### / ####` |

> **单源保证**：`renderDocsHtml()` 与 `buildMarkdown()` 遍历同一 `DOC_SECTIONS`；
> 每块数据里的 `md` 字段就是 MD 原文（表格/代码直接用字符串），页面侧再 escape 后展示。
> 唯一差异仅是 HTML 转义与代码高亮，语义内容完全相同。

## 5. Markdown 下载实现（关键设计）

遵循现有代码风格（`common.js` 工具 + api.js 无涉），`docs.js` 内实现：

```js
/** 构建完整 Markdown：BOM + 标题 + 版本行 + 各节（与页面渲染同源）。 */
function buildMarkdown() {
  const lines = [];
  lines.push('# AuthCenter 接入对接文档');
  lines.push('');
  lines.push('> 版本：v1.0（与当前部署的 AuthCenter 一致）｜ 适用于项目接入方开发人员');
  lines.push('');
  DOC_SECTIONS.forEach((sec) => {
    lines.push(`## ${sec.title}`, '');
    sec.blocks.forEach((b) => pushBlock(lines, b));   // 按块类型拼接 MD
    lines.push('', '---', '');
  });
  return lines.join('\n');
}

/** 下载：Blob + ObjectURL + 隐藏 <a> 触发，BOM 防 Windows 记事本中文乱码。 */
function downloadDoc() {
  const md = buildMarkdown();
  const blob = new Blob(['\ufeff' + md], { type: 'text/markdown;charset=utf-8' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = 'AuthCenter-接入对接文档.md';
  document.body.appendChild(a);
  a.click();
  a.remove();
  setTimeout(() => URL.revokeObjectURL(url), 1000);
  toast('对接文档已下载', 'success');
}
```

设计要点：

| 要点 | 说明 |
|------|------|
| 文件名 | `AuthCenter-接入对接文档.md`（固定，便于团队内统一存档） |
| 编码 | 加 `\ufeff`（UTF-8 BOM），避免 Windows 记事本打开中文乱码 |
| 无需后端 | 内容全在前端常量，离线可用、可内嵌发布（符合 01 §6 无外部资源约束） |
| 下载按钮交互 | 点击即下载（内容静态无需等待）；失败（极端环境）`toastError` 兜底 |
| 版本自述 | MD 顶部含「版本/适用范围」行，避免开发人员拿到过期版本误用 |

## 6. 对接文档完整内容定义（页面 + MD 共同内容）

> 以下即「下载按钮」将产出的完整文档结构。各字段作用/意义已逐条与源码核对
> （`handlers_auth.go`、`auth_service.go`、`token_service.go`、`respond.go`、`version.go`）。

### 一、概述与接入流程
- AuthCenter 是什么：内部中心认证服务，其他项目程序携带「项目名 + 版本号 + 指纹 + 分配密钥」
  调用认证接口，校验通过返回认证结果（可选签发短期访问令牌）。
- 接入四步：
  1. **开户**：联系 AuthCenter 管理员创建项目（拿到唯一 `project_name`）并生成密钥（拿到 40 位 `key`，注意仅展示一次）；
  2. **约定指纹**：与管理员确认是否绑定指纹；若绑定，客户端必须计算并携带相同指纹；
  3. **调用认证接口**：程序启动时（或定时/按需）携带四要素调用 `POST /api/v1/authenticate`；
  4. **处理结果**：`code == 0` 即通过；否则按业务码排错（见错误码表）。

### 二、服务地址与 Base URL
| 环境 | Base URL |
|------|----------|
| 本机（开发/内网直连） | `http://127.0.0.1:53779` |
| 对外（Caddy 反代 HTTPS） | `https://auth.example.com`（以管理员实际分配为准） |
- 接口路径前缀：`/api/v1`；请求/响应均为 `application/json; charset=utf-8`；
- 健康检查（连通性验证）：`GET /healthz` → 200 `ok`。

### 三、认证接口 POST /api/v1/authenticate

**请求参数表（请求体 JSON）**：

| 字段 | 类型 | 必填 | 长度/取值 | 作用与意义 |
|------|------|------|-----------|------------|
| `project_name` | string | ✅ | 与管理员创建的项目名**完全一致**（区分大小写） | 标识调用方项目；后端按此查找项目配置（版本限制、状态） |
| `version` | string | ✅ | 语义化版本建议 `主.次.修订`，如 `1.2.3` | 项目当前版本；后端与项目 `min_version` 比较，低于最低版本拒绝 |
| `fingerprint` | string | ✅ | 1-128 字符，如 `sha256(机器ID)[:32]` | 客户端指纹；密钥绑定指纹时须精确匹配；系统开启强制策略时未绑定指纹的密钥一律拒绝 |
| `key` | string | ✅ | 40 位 `A-Za-z0-9` | 管理员分配的密钥；后端按此查密钥状态（启用/过期/归属） |
| `issue_token` | bool | ❌ 默认 `false` | `true`/`false` | 是否签发 JWT 访问令牌；仅当认证通过且为 `true` 时签发 |

**请求示例**：

```jsonc
// 仅认证
{
  "project_name": "my-service",
  "version": "1.2.3",
  "fingerprint": "a1b2c3d4e5f6a7b8c9d0",
  "key": "Kx8AbC...（40位）",
  "issue_token": false
}
// 认证并签发令牌
{ "project_name": "my-service", "version": "1.2.3",
  "fingerprint": "a1b2c3d4e5f6a7b8c9d0", "key": "Kx8AbC...", "issue_token": true }
```

**响应结构通用约定**：成功 `{code:0, message:"ok", data:{...}}`；失败 `{code, message, request_id}`。
**注意：认证接口 HTTP 一律 200**（除服务器内部错误为 500），业务结果放 `code`，客户端只看 `code`。

**成功响应（code:0）data 字段表**：

| 字段 | 类型 | 作用与意义 |
|------|------|------------|
| `authenticated` | bool | 恒为 `true`（成功时） |
| `project.name` | string | 认证通过的项目名（回显，供核对） |
| `project.current_version` | string | 项目当前维护版本（客户端可据此提示升级） |
| `server_time` | string(ISO8601 UTC) | 服务端当前时间，用于客户端时间校准 |
| `token` | object/null | `issue_token=true` 时签发；否则为 `null` |

`token` 对象：`{ "token": "eyJ...", "algorithm": "HS256", "expires_at": "2026-01-02T00:00:00Z" }`。

**失败响应（HTTP 仍为 200）data 字段**：`{ "authenticated": false, "reason": "key_expired" }`
（`reason` 为机器可读原因码，与业务码一一对应，见错误码表）。

### 四、错误码速查表（认证接口专用）

| 业务码 | reason | 含义 | 客户端处置建议 |
|--------|--------|------|----------------|
| 0 | — | 认证通过 | 放行 |
| 10001 | `project_not_found` | 项目不存在 | 核对 `project_name` 与管理员创建是否一致 |
| 10002 | `project_disabled` | 项目已停用 | 联系管理员启用 |
| 10003 | `version_too_old` | 版本低于项目最低版本 | 升级程序版本 |
| 10004 | `key_not_found` | 密钥不存在/不属于该项目 | 核对 `key` 是否正确、密钥是否属于该项目 |
| 10005 | `key_disabled` | 密钥已停用 | 联系管理员启用密钥 |
| 10006 | `key_expired` | 密钥已过期 | 联系管理员轮换/生成新密钥 |
| 10007 | `fingerprint_mismatch` | 指纹与绑定不一致 | 核对指纹算法与取值 |
| 10008 | `fingerprint_required` | 未绑定指纹但系统要求绑定 | 联系管理员绑定指纹或启用强制策略前完成绑定 |
| 10009 | `rate_limited` | 触发限流 | 退避重试（见 §八） |

通用错误码（400/401/404/409/429/500 与对应 HTTP 状态）：
`20001 参数缺失/非法`、`20002 JSON 解析失败`、`20003 校验失败`、`50000 服务器内部错误`。
（管理 API 的 `20101-20104、20200-20202` 与接入方无关，文档中不展开。）

### 五、认证校验顺序（排错参考）

后端按如下顺序校验，**失败即返回并写审计**（对客户端不暴露密钥归属细节）：

```
1  IP 限流（默认 100 次/分钟）        → 10009 rate_limited
2  项目存在（project_name 精确匹配）   → 10001 project_not_found
3  项目启用                           → 10002 project_disabled
4  版本 ≥ min_version（语义化比较）    → 10003 version_too_old
5  密钥存在（key 精确匹配）            → 10004 key_not_found
6  密钥属于该项目                      → 10004（对外不区分，审计记 key_mismatch）
7  密钥启用                           → 10005 key_disabled
8  密钥未过期                         → 10006 key_expired
9  指纹校验（绑定精确匹配/强制策略）     → 10007 / 10008
10 更新密钥最后使用时间/IP（60s 窗口）
11 写审计 success
12 可选：签发 JWT（issue_token=true）
```

### 六、字段详解

- **版本比较规则**（宽松语义化）：按 `.` 分段比较数字主三段（缺省补 0），`-beta`/`+build` 后缀忽略；
  例如客户端 `1.10.0` 与 `min_version=1.9` 比较 → 通过；`1.8.9` 与 `1.9` → 拒绝（`version_too_old`）。
- **指纹约定**：建议 `sha256(机器唯一ID)` 取前 32 位 hex；指纹**大小写敏感、需与管理员绑定值完全一致**。
- **密钥生命周期**：密钥可能永不过期（`expires_at` 为 null）或带过期时间；轮换后旧密钥进入 7 天宽限期（宽限期内仍可认证）。

### 七、可选 JWT 令牌（issue_token=true 时）

- 算法：`HS256`；issuer：`authcenter`；有效期：默认 24h（服务端 `settings.token_ttl_seconds` 可配）。
- Claims（payload）说明：

| 字段 | 含义 |
|------|------|
| `sub` | `project:{project_name}`，如 `project:my-service` |
| `pid` | 项目 ID（int） |
| `kid` | 密钥 ID（int，用于追踪是哪个密钥签发的） |
| `ver` | 认证时的项目版本 |
| `iat` / `exp` | 签发时间 / 过期时间（Unix 秒） |
| `jti` | 唯一令牌 ID（随机） |
| `iss` | `authcenter` |

- **校验方式**：调用方可自持 `jwt_secret`（由管理员通过环境变量 `AUTHCENTER_JWT_SECRET` 共享）
  本地校验签名 + `exp` + `iss`；或每次调用本服务认证接口换取新令牌。
- 安全提示：令牌是短期凭证，不要在日志中打印；用于后续受保护接口的授权头 `Authorization: Bearer <token>`。

### 八、限流与审计

- 认证接口限流：**每 IP 每分钟 100 次**（服务端可配 `rate_limit_auth_per_min`）；超限返回 `10009`，
  客户端应退避重试（建议指数退避，至少等待 1 分钟窗口）。
- 每次认证（成功/失败）都会写入审计日志：成功 `auth.authenticate`、失败 `auth.authenticate_failed`
  （detail 含失败原因、版本、指纹、IP；**不含密钥明文**），管理员可在审计页追溯。

### 九、调用示例

```bash
# curl（仅认证）
curl -s -X POST http://127.0.0.1:53779/api/v1/authenticate \
  -H 'Content-Type: application/json' \
  -d '{"project_name":"my-service","version":"1.2.3","fingerprint":"a1b2c3d4...","key":"Kx8AbC..."}'
# 返回：{"code":0,"message":"ok","data":{"authenticated":true,...}}
```

```python
# Python 3（urllib 标准库）
import json, urllib.request
req = urllib.request.Request(
    "http://127.0.0.1:53779/api/v1/authenticate",
    data=json.dumps({"project_name": "my-service", "version": "1.2.3",
                     "fingerprint": "a1b2c3d4", "key": "Kx8AbC...",
                     "issue_token": False}).encode(),
    headers={"Content-Type": "application/json"})
with urllib.request.urlopen(req) as r:
    data = json.load(r)
if data["code"] == 0:
    print("认证通过", data["data"]["project"]["current_version"])
```

```go
// Go（标准库）
body, _ := json.Marshal(map[string]any{
    "project_name": "my-service", "version": "1.2.3",
    "fingerprint": "a1b2c3d4", "key": "Kx8AbC...", "issue_token": false,
})
resp, err := http.Post("http://127.0.0.1:53779/api/v1/authenticate",
    "application/json", bytes.NewReader(body))
// 解析 {"code":0,...}，code==0 即通过（HTTP 恒为 200，勿按状态码判断）
```

> 通用要点：**一律解析 JSON body 的 `code` 判断结果**，不要依赖 HTTP 状态码；
> 网络错误/5xx 视为服务不可用，做重试。

### 十、常见失败排查表

| 现象 | 原因 | 处理 |
|------|------|------|
| `10001 project_not_found` | 项目名拼写不一致/项目被删 | 与管理员核对项目名 |
| `10003 version_too_old` | 版本号比 min_version 低 | 升级客户端版本号（保持与发布版本一致） |
| `10006 key_expired` | 密钥过期/轮换后旧密钥超宽限期 | 申请新密钥 |
| `10007 fingerprint_mismatch` | 指纹不一致（换机器/大小写/算法差异） | 统一指纹算法与取值，或让管理员解绑 |
| `10009 rate_limited` | 频繁调用（>100 次/分钟/IP） | 退避重试、合并请求 |
| 连不上 / 超时 | 服务未启动 / 端口不通 / Caddy 配置 | `curl http://127.0.0.1:53779/healthz` 应返回 `ok` |

### 十一、安全建议

1. 密钥是敏感凭证：写入程序配置/环境变量，**勿硬编码进源码、勿提交版本库**；
2. 定期轮换密钥（管理员侧操作），轮换宽限期 7 天，两端做好新旧切换；
3. 高价值项目绑定指纹，防止密钥被拷贝到其他机器使用；
4. 认证请求走 HTTPS（对外经 Caddy 反代），避免密钥明文在公网传输；
5. 令牌（JWT）短期有效，按需申请（`issue_token` 默认关闭），不要在日志打印；
6. 关注审计页中自己项目的认证失败记录，异常尝试及时上报管理员。
