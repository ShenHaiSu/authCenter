## 4. 实现要点记录（对照文档）

1. **校验链 12 步**（04 §3.2）：限流 → 项目存在/启用 → 版本校验 → 密钥存在/归属/启用/未过期 → 指纹（绑定精确匹配 + require_fingerprint 强制策略）→ last_used 低频更新 → 审计成功 → 可选签发。
2. **key_mismatch 语义**：校验链第 6 步「密钥不属于该项目」对外映射为 `key_not_found`（10004），审计 detail 记 `key_mismatch`——遵循 05 §2 错误码表（无 key_mismatch 码）且不泄露密钥归属（安全设计 06 §11 权衡）。
3. **认证响应 HTTP 一律 200**：认证专用业务码 10001-10009（含限流）均 HTTP 200，客户端只看 `code==0`；仅服务器内部错误（50000）用 HTTP 500（05 §2/§3.1 设计说明）。
4. **令牌 Claims**（04 §3.3）：`{sub:"project:{name}", pid, kid, ver, iat, exp, jti}`；secret 读 settings.jwt_secret（env 覆盖优先，M1 已实现）；TTL 读 settings.token_ttl_seconds（默认 86400）。
5. **认证限流**（06 §7）：IP 令牌桶（golang.org/x/time/rate），默认 100 次/分钟，`settings.rate_limit_auth_per_min` 可配；last_used 60s 窗口低频更新防写放大（04 §7）。
6. **脱敏**：认证审计 detail 只记 version/fingerprint/key_id/reason，不含密钥明文与密码明文（06 §6）。
7. **版本比较**：宽松语义化（缺段补 0、忽略预发布后缀），min_version 由管理员配置，宽松解析避免误拒。

## 5. 基准测试结果（性能冒烟，对照文档 01 §5 / 08 §6）

环境：Windows 11 / Intel i7-9750H 2.60GHz / Go 1.26.5 / SQLite WAL（单连接）

| Benchmark | 结果 | 说明 |
|-----------|------|------|
| BenchmarkAuthenticateSuccess | **2.19 ms/op**（5.4 KB/op, 147 allocs/op） | 认证主路径：项目+密钥 2 次索引查询 + 审计写入（WAL fsync）+ 校验链内存判断 |

性能预算分析（文档 01 §5：认证接口 **P99 < 50ms、≥ 100 QPS**）：

```
单请求 ≈ 2.2ms → 单实例理论吞吐 ≈ 455 QPS（单连接串行）> 100 QPS 目标 4.5×
P99 远低于 50ms 预算（余量约 22×）
```

- 与 M1 预算（1.9ms）基本吻合，审计写入仍是主要成本（1.85ms）；高频场景可复用「审计异步化」预留策略。
- **结论**：M3 认证链路性能达标，无优化紧迫性。
