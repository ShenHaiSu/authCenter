# 02 系统总体架构

> 后端架构文档 2/8

## 1. 总体架构图

```
                        ┌─────────────────────────────────────────────┐
                        │                  本机 (127.0.0.1)            │
                        │                                             │
  其他项目程序           │   ┌─────────────────────────────────────┐   │
 ┌─────────────┐  HTTP  │   │        AuthCenter (Go 二进制)       │   │

 │ Project B   │        │   │  ┌───────────────────────────────┐  │   │

        │   Caddy       │   │  │  服务层: auth/project/key/    │  │   │
        │ (HTTPS 443)   │   │  │         token/audit/service   │  │   │
        │ 反代到 53779  │   │  └───────────────┬───────────────┘  │   │
        └───────────────┘   │  ┌───────────────▼───────────────┐  │   │

                        │   │  └───────────────┬───────────────┘  │   │
```

要点：
1. **单一端口**：`127.0.0.1:53779` 同时承载「前端静态页面」与「全部 API」，同源无跨域问题。
2. **对外唯一入口**：Caddy 承担 HTTPS 终止与反向代理，把公网/局域网请求转发到本机 53779。
3. **数据自包含**：SQLite 单文件 + 日志文件，全部位于数据目录（默认 `data/`），可整体备份迁移。

## 2. 分层设计

| 层 | 职责 | 关键实现 |
|----|------|----------|
| HTTP 层 | 路由、中间件、请求/响应编解码、静态资源服务 | 标准库 `net/http`（Go 1.22+ 方法路由）、`http.FileServer` + `embed.FS` |
| 中间件 | 请求日志、Panic 恢复、`X-Request-Id`、会话鉴权、限流、请求体限制 | 自研轻量中间件链 |
| 服务层 | 业务规则：认证校验链、项目/密钥 CRUD、令牌签发、审计写入 | 纯函数式 service，不感知 HTTP |
| 数据层 | SQLite 访问、迁移、事务 | `database/sql` + `modernc.org/sqlite`（纯 Go，无 cgo） |

依赖方向：`HTTP 层 → 服务层 → 数据层`，禁止反向依赖；服务层与数据层以接口隔离，便于单测。

## 3. 技术选型与理由

| 组件 | 选型 | 理由与备选 |
|------|------|------------|
| 语言 | Go 1.22+ | 需求红线 C1；Go 1.22 标准库 ServeMux 支持 `"GET /path/{id}"` 方法+路径参数，无需框架 |
| SQLite 驱动 | `modernc.org/sqlite` | **纯 Go**（cgo 红线唯一解）；备选 `zombiezen.com/go/sqlite`（API 非标准，弃）；`mattn/go-sqlite3` 需 cgo，**禁用** |
| 密码哈希 | `golang.org/x/crypto/argon2`（argon2id） | 纯 Go、内存困难抗暴力破解；备选 bcrypt（72 字节限制，弃） |
| JWT | `github.com/golang-jwt/jwt/v5` | 纯 Go、标准实现；签名算法 HS256（secret 随机生成） |
| 限流 | `golang.org/x/time/rate` | 纯 Go 令牌桶；按 key 维护独立 limiter |
| 日志 | `log/slog` | 标准库结构化日志，JSON/文本可切换 |
| 静态嵌入 | `embed` | 前端构建期复制进 `BackEnd/internal/web/` 后 `//go:embed all:web` |
| 配置 | `flag` + 环境变量 | 无配置文件依赖，保持单二进制简洁（详见后端文档 04） |

> 第三方依赖合计 ≤ 4 个，且全部纯 Go。验收时以 `go list -deps` 核对无 CGO 依赖。

## 4. 后端目录结构（目标态）

```
BackEnd/
├── go.mod / go.sum
├── cmd/
│   └── authcenter/
│       └── main.go                 # 入口：装配 config → db → service → http server
├── internal/
│   ├── config/                     # 配置解析（flag + env）
│   ├── database/                   # 打开连接、PRAGMA、迁移（建表）
│   ├── model/                      # 领域结构体（Project/APIKey/AdminUser/AuditLog/Session…）
│   ├── store/                      # 数据访问层（database/sql，按实体拆分文件）
│   ├── service/                    # 业务层：auth / project / apikey / token / audit / session
│   ├── httpapi/                    # HTTP 层：router、handlers、middleware、响应编解码
│   └── web/                        # 前端静态资源（构建期由 FrontEnd/ 复制而来，gitignore）
└── build.ps1 / build.sh            # （也可放仓库根目录，见后端文档 07）
```

> 目录命名：Windows 文件系统不区分大小写，因此统一使用小写包名，避免跨平台 checkout 冲突。

## 5. 前端集成方式（关键决策）

- 开发期：`FrontEnd/` 独立存放，可直接用任意静态服务器打开调试；后端以 `dev` 模式（flag `-web-dir`）从磁盘目录服务静态文件，便于热改。
- 发布期：构建脚本将 `FrontEnd/*` 复制到 `BackEnd/internal/web/`，`go:embed all:web` 编译进二进制；运行时由同一个 53779 端口提供页面与 API。
- Bundle 附加：`Bundle/{windows,linux}/web/` 同时保留一份前端静态文件副本（满足需求 C6「前后端产物同时复制」），也便于后续切换为 Caddy/Nginx 直接托管。

## 6. 启动流程

```
main.go
 ├─ 1. 解析配置（-data-dir、-listen 默认 127.0.0.1:53779、-log-level…）
 ├─ 2. 初始化结构化日志（slog，文本/JSON）
 ├─ 3. 打开 SQLite（data/authcenter.db）
 │     ├─ PRAGMA journal_mode=WAL; busy_timeout=5000; foreign_keys=ON
 │     └─ 执行迁移（CREATE TABLE IF NOT EXISTS …）
 ├─ 4. 初始化服务层（session / project / apikey / token / audit / auth）
 ├─ 5. 初始化 admin（幂等）：
 │     ├─ SELECT 存在 admin ？ 跳过
 │     └─ 不存在 → crypto/rand 生成 30 位密钥 → argon2id 哈希入库
 │           → 控制台打印明文 → 写入 data/auth.log → 输出告警日志
 ├─ 6. 生成/读取 JWT secret（settings 表，可被 env AUTHCENTER_JWT_SECRET 覆盖）
 ├─ 7. 装配路由与中间件（web 静态服务 + /api/v1 路由组）
 └─ 8. http.Server{Addr:"127.0.0.1:53779", 超时参数} ListenAndServe
       └─ 优雅关闭（SIGINT/SIGTERM，等待在途请求完成）
```

## 7. 关键数据流

### 7.1 外部项目认证（核心链路）

```
客户端                              AuthCenter
  │ POST /api/v1/authenticate        │
  │ {project_name,version,fingerprint,key,issue_token?} │
  │─────────────────────────────────►│
  │                                  │ 1. 限流检查
  │                                  │ 2. 查 project（存在？启用？）
  │                                  │ 3. 查 api_key（project_id + key 匹配？启用？未过期？）
  │                                  │ 4. 指纹校验（密钥绑定了指纹？一致？）
  │                                  │ 5. 写审计（成功/失败 + 原因 + 指纹 + IP）
  │                                  │ 6. 可选：签发 JWT（更新 last_used_at）
  │ 200 {authenticated, project,    │
  │      token?}                     │
  │◄─────────────────────────────────│
```

### 7.2 管理员操作（以生成密钥为例）

```
浏览器 → 登录(会话) → POST /api/v1/projects/{id}/keys
  → 会话校验 → 业务校验（项目启用）→ 生成密钥（crypto/rand 40 位）
  → 明文仅本次响应返回 → 写审计 → 响应
```

## 8. 非功能架构决策

| 决策 | 内容 |
|------|------|
| 无状态性 | 除 SQLite 与内存限流器外无状态，便于单实例部署；不设计多实例（本机单实例场景） |
| 时区 | 统一存储 UTC 时间戳，前端展示时按浏览器本地时区格式化 |
| 错误处理 | 服务层返回业务错误码，HTTP 层统一映射 HTTP 状态码 + `{code,message,request_id}` |
| 资源限制 | `http.Server` 设置 `ReadHeaderTimeout=5s`、`ReadTimeout=15s`、`WriteTimeout=15s`、`MaxHeaderBytes=1MB`；请求体 `http.MaxBytesReader` 限制 1MB |
