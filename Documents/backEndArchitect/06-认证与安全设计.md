# 06 认证与安全设计

> 后端架构文档 6/8 ｜ 威胁模型、认证因素、密码/会话/令牌/指纹、限流、应急、传输

## 1. 信任边界与威胁模型

```
            不可信侧                        可信侧（本机）
   ┌─────────────────────┐        ┌──────────────────────────┐
   │ 公网/局域网客户端     │        │  127.0.0.1:53779         │
   │  - 恶意项目程序       │  HTTPS │   AuthCenter             │
   │  - 攻击者（能访问网络）│───────►│   - 数据目录 data/       │
   │  - 管理员浏览器       │ Caddy  │   - SQLite 文件          │
   └─────────────────────┘        │   - auth.log             │
                                  └──────────────────────────┘
```

| 威胁 | 场景 | 缓解（本文档节） |
|------|------|------------------|
| T1 密钥泄露 | 项目密钥被截获/泄露 | 指纹绑定(§4)、轮换/吊销(§5)、审计(§6) |
| T2 暴力破解 | 猜测 admin 密码或密钥 | argon2id(§3)、登录限流+锁定(§7) |
| T3 会话劫持 | 窃取管理员会话 cookie | httpOnly+SameSite、服务端会话、短 TTL(§3.2) |
| T4 数据库文件泄露 | 本机其他进程读到 db | 目录/文件权限 0700/0600(§8) |
| T5 日志泄露明文 | 日志中含密钥/密码 | 脱敏红线(§6) |
| T6 重放攻击 | 截获认证请求重放 | 密钥认证本身无状态（重放=再认证，可接受）；令牌短 TTL + 可选 jti 黑名单(P2) |
| T7 中间人 | HTTP 明文被嗅探 | 对外必须 Caddy HTTPS(§9)，服务仅本机监听 |

## 2. 认证因素设计

外部项目认证 = **持有的密钥**（something you have）+ **指纹绑定**（可选，environment attestation）。

- 密钥：40 位随机（A-Za-z0-9，熵 238bit），crypto/rand 生成。
- 指纹：客户端环境的稳定标识（见 §4），可绑定到密钥；绑定后只有携带该指纹的客户端能认证成功。
- 设计原则：**指纹防扩散，密钥防伪造**——即使密钥泄露，未绑定的攻击者因指纹不符无法使用。

## 3. 密码与密钥存储

### 3.1 admin 密码哈希（argon2id）

- 算法参数（内存困难抗 GPU）：`memory=64MB, iterations=3, parallelism=2, salt=16B, key=32B`（`golang.org/x/crypto/argon2` 标准封装）。
- 存储格式：`$argon2id$v=19$m=65536,t=3,p=2$<salt_b64>$<hash_b64>`，校验时按串内参数重算。
- 新密码强度要求：≥ 12 位，必含字母与数字（前端+后端双重校验）。

### 3.2 会话 token

- 登录成功生成 32B 随机 token → 库中只存 `SHA-256(token)` → 下发 cookie。
- Cookie：`auth_session`；`HttpOnly; SameSite=Lax; Path=/; Max-Age=604800`（7 天）。
- 库中明文 token 不可见 → 即使 db 泄露也无法伪造会话。
- 登出/改密即删会话；改密使全部会话失效。

### 3.3 项目密钥存储

- 默认明文存 `api_key.key_value`（内部工具，需界面复制下发）。
- 缓解：`data/` 目录权限 0700、db 文件 0600；服务仅监听 127.0.0.1。
- 可选升级（F-021）：AES-256-GCM 加密密钥列，密钥来自 env `AUTHCENTER_KEY_ENCRYPTION_KEY`。

### 3.4 JWT secret

- 首次启动 `crypto/rand` 生成 32B，base64 存 `settings.jwt_secret`。
- 可被 env `AUTHCENTER_JWT_SECRET` 覆盖（备份恢复场景必需，否则历史令牌全部失效）。

## 4. 指纹规范

| 项 | 规定 |
|----|------|
| 格式 | 1-128 字符，建议 `[A-Za-z0-9_-]`；大小写敏感，精确匹配 |
| 生成建议 | 客户端持久化一段稳定标识并哈希：如 `sha256(机器ID + 安装路径 + 随机salt)[:32]`；重启不变、跨版本不变 |
| 绑定 | 创建/编辑密钥时可填 `fingerprint`；未绑定 = 任意指纹可认证 |
| 强制策略 | `settings.require_fingerprint=1` 时，未绑定指纹的密钥一律拒绝（fingerprint_required） |
| 记录 | 每次认证的指纹写入审计 detail，便于追溯 |

## 5. 密钥泄露应急（T1）

1. **立即吊销**：管理界面 `DELETE /keys/{id}`（即刻失效）或 `is_active=0`。
2. **轮换**：`POST /keys/{id}/rotate` 生成新密钥，旧密钥保留 7 天宽限期（默认）供灰度切换，期满自动禁用。
3. **审计追查**：`audit_log` 中按 key_id 检索该密钥全部认证记录（含指纹、IP、时间），判断泄露面。
4. **指纹绑定**：新密钥建议绑定指纹，缩小可用的客户端范围。

## 6. 审计与日志脱敏

- 全量审计（决策 D2）：事件类型见《03》§5、《05》§5。
- **脱敏红线**：日志/审计/响应体中不得出现密钥明文、密码明文、会话 token 明文。
- admin 初始密码例外通道：仅 `data/auth.log`（0600）+ 控制台，且只在**首次生成时**写入一次（幂等保证不会重复出现）。
- 认证失败审计 detail 只记原因码（如 `key_expired`），不记提交的密钥值。

## 7. 防暴力破解（T2）

| 接口 | 策略（内存令牌桶 `golang.org/x/time/rate`） |
|------|------|
| POST /admin/login | 每 IP 5 次/分钟；同一用户名连续失败 5 次锁定 15 分钟（返回统一错误，不泄露账号是否存在） |
| POST /authenticate | 每 IP 100 次/分钟（可配置 `settings.rate_limit_auth_per_min`） |
| 通用 | 全局连接数限制（`http.Server` + 中间件，防 SYN/慢速攻击：ReadHeaderTimeout=5s） |

锁定事件写审计（`admin.login_failed` / `auth.authenticate_failed`）。

## 8. 文件与数据保护

| 项 | 措施 |
|----|------|
| 数据目录 | 默认 `data/`，启动时创建并 `chmod 0700`（POSIX；Windows 依赖用户目录 ACL） |
| db 文件 | `0600`（POSIX）；SQLite WAL 的 `-wal/-shm` 同权限 |
| auth.log | `0600` |
| 备份 | 文档化 `sqlite3 .backup`；提示备份含密钥，须与 JWT secret 一起保存 |

## 9. 传输安全（R2：HTTPS 交给 Caddy）

- AuthCenter **只监听 127.0.0.1**，不直接暴露公网。
- Caddy 反代示例（Caddyfile）：

```
auth.example.com {
    reverse_proxy 127.0.0.1:53779
    # Caddy 自动申请/续期 HTTPS 证书；如需局域网 IP 访问可加 tls internal
}
```

- 安全加固建议：
  - Caddy 侧限制 `header_up Host` 固定、开启访问日志。
  - 若需局域网直连本机管理（临时），仅在可信网络进行，否则一律走 Caddy HTTPS。
- **禁止**在 AuthCenter 内实现 TLS（需求红线：http 协议，TLS 归属 Caddy）。

## 10. 依赖与供应链

- 第三方依赖仅 4 个且全部纯 Go；`go.sum` 锁定版本。
- 验收：`CGO_ENABLED=0 go list -deps ./... | grep -i cgo` 应为空；`go vet ./...` 无告警。
- 定期 `go get -u` + 安全审计（`govulncheck` 可选，纯 Go 工具）。

## 11. 安全验收检查清单

- [ ] `CGO_ENABLED=0` 交叉编译两平台通过
- [ ] admin 初始化幂等（重启不重复生成密码）
- [ ] 登录 5 次失败后锁定 15 分钟
- [ ] 认证失败不区分"项目不存在/密钥错误"对外提示（统一 bad_credentials 风格可选）——注意：认证接口按业务码区分便于排查，权衡后保留业务码，登录接口统一提示
- [ ] 日志/审计无明文密钥/密码（代码评审 + 抓日志验证）
- [ ] 指纹绑定后，错误指纹认证返回 fingerprint_mismatch 且写审计
- [ ] 过期密钥返回 key_expired；吊销密钥即刻失效
