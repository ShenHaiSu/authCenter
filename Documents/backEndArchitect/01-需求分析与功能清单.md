# 01 需求分析与功能清单

> 后端架构文档 1/8 ｜ 输入：用户原始需求（5 条）+ 用户拍板决策（4 项）

## 1. 需求背景

作者在本地开发多套项目程序（Go / 其他语言），需要一个轻量、可靠、可离线运行的**内部认证中心**：统一管理各项目程序的访问密钥，供项目程序启动/调用时校验合法性，同时提供一个最小的 Web 管理界面维护密钥。系统定位为**个人/小团队内部基础设施**，不做公网开放业务。

## 2. 原始需求逐条分析

| # | 原始需求 | 解读与设计落点 |
|---|----------|----------------|
| R1 | 后端纯 Go，禁止 cgo | ①所有依赖必须是纯 Go；②构建必须 `CGO_ENABLED=0`；③SQLite 驱动选 `modernc.org/sqlite`；④CI/验收含"无 cgo 交叉编译"验证 |
| R2 | 仅监听 127.0.0.1:53779，HTTP，HTTPS 由 Caddy 完成 | ①`http.Server` 绑定 `127.0.0.1:53779`；②不开 TLS；③对外暴露路径由 Caddy 反代；④文档给出 Caddyfile 示例 |
| R3 | 启动自动生成 admin，密码 30 位纯随机文本，已存在则跳过 | ①启动时检查 `admin_user` 表是否有 admin；②无则生成 30 位随机密钥（`crypto/rand`，A-Za-z0-9 字符集）；③哈希后入库；④明文打印控制台 + 写入 `data/auth.log`；⑤幂等 |
| R4 | 其他项目程序带「项目名+版本号+指纹+密钥」连接，后端返回认证结果 | ①设计 `POST /api/v1/authenticate`；②校验链：项目存在且启用 → 密钥存在且启用 → 未过期 → 指纹匹配（可配置绑定）→ 返回结果；③可选签发短期令牌（决策 D1）；④全量写审计（决策 D2） |
| R5 | 前端 html+css+js 简单界面：管理员登录、密钥生成、过期时间管理、密钥备注等 | ①原生三件套；②页面：登录、仪表盘、项目管理、密钥管理、审计日志、修改密码；③密钥支持备注/过期时间/启停/轮换/指纹 |

## 3. 已确认决策输入（详见 README 第 3 节）

- **D1** 认证返回「结果 + 可选令牌」：默认 `issue_token=false` 只返回结果；为 true 时签发 JWT。
- **D2** 完整审计：管理端登录/登出、项目与密钥增删改、外部认证成功/失败，均可查。
- **D3** admin 初始密码：控制台打印 + 落盘 `data/auth.log`，之后不再展示。
- **D4** 一项目多密钥：支持轮换、单独过期时间/备注、启用/禁用、指纹绑定。

## 4. 功能清单

### 4.1 P0（必须，第一版交付）

| 编号 | 功能 | 说明 | 对应需求 |
|------|------|------|----------|
| F-001 | HTTP 服务骨架 | 纯 Go、`127.0.0.1:53779`、超时/请求体限制、`X-Request-Id` | R1/R2 |
| F-002 | 启动初始化 | 建库、建表、自动创建 admin（幂等）、生成 JWT secret | R3 |
| F-003 | admin 密码交付 | 控制台打印 + `auth.log` 落盘，仅首次 | R3/D3 |
| F-004 | 管理员登录/登出/改密 | 会话鉴权（服务端 session + httpOnly cookie） | R5/D2 |
| F-005 | 项目管理 | 创建/查看/编辑/删除/启停用；维护当前版本与可选最低版本 | R4/R5 |
| F-006 | 密钥管理 | 生成（明文一次性展示）、多密钥、备注、过期时间、启用/禁用、删除（吊销） | R4/R5/D4 |
| F-007 | 密钥指纹绑定 | 可绑定/解绑指纹；未绑定则任意指纹可认证（可全局配置强制绑定） | R4 |
| F-008 | 对外认证 API | `POST /api/v1/authenticate`，完整校验链 + 审计 | R4/D1 |
| F-009 | 完整审计 | 审计表 + 查询 API + 前端审计页 | D2 |
| F-010 | 前端管理界面 | 登录/仪表盘/项目/密钥/审计/改密 | R5 |
| F-011 | 前端内嵌 | `go:embed` 将前端打包进二进制，单一端口服务 | R2/C5 |
| F-012 | Bundle 构建 | 交叉编译两平台产物，前后端同时复制到 `Bundle/windows` 与 `Bundle/linux` | C6 |

### 4.2 P1（增强，第一版尽量含）

| 编号 | 功能 | 说明 |
|------|------|------|
| F-013 | 令牌签发 | `issue_token=true` 时签发 JWT，TTL 可配置（默认 24h），secret 可被环境变量覆盖 |
| F-014 | 登录防爆破 | 登录接口限流（IP+用户名维度，5 次/分钟，超限锁定 15 分钟）；认证接口限流 |
| F-015 | 密钥轮换 | `POST /api/v1/keys/{id}/rotate`：生成新密钥，旧密钥可选保留宽限期后自动失效 |
| F-016 | 过期密钥提示 | 仪表盘与密钥列表标注「即将过期/已过期」，默认 7 天内提醒 |
| F-017 | 配置管理 | 数据目录、日志级别、令牌 TTL、指纹策略等通过 flag/env 配置 |

### 4.3 P2（后续迭代）

| 编号 | 功能 | 说明 |
|------|------|------|
| F-018 | 仪表盘统计 | 今日认证次数、成功/失败比、活跃项目 TOP、密钥到期分布 |
| F-019 | 审计保留策略 | 可配置审计日志保留天数，自动清理 |
| F-020 | 多管理员与 RBAC | admin 支持新增/停用，角色预留（预留 `role` 字段，不做复杂权限） |
| F-021 | 密钥存储加密 | 可选 AES-GCM 加密密钥列（密钥来自环境变量），缓解明文落盘风险 |

## 5. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 认证接口 P99 < 50ms（本机 SQLite）；管理接口 P99 < 100ms |
| 并发 | 单实例支撑 ≥ 100 QPS 认证请求；SQLite WAL + busy_timeout 缓解写锁 |
| 兼容 | Go 1.22+；`CGO_ENABLED=0` 下交叉编译 windows/amd64 与 linux/amd64（arm64 可选） |
| 可靠性 | 崩溃后自动恢复（SQLite 事务 + WAL）；启动自检（建库/建表失败即退出并报错） |
| 安全 | 见《06-认证与安全设计》：密码 argon2id、会话随机 token、日志脱敏、文件权限 |
| 可部署 | Windows 直接运行/可选 NSSM 服务；Linux systemd；单二进制，数据目录自包含 |
| 可维护 | 结构化日志（slog）、全链路 `X-Request-Id`、审计可追溯 |

## 6. 范围外事项（明确不做）

- ❌ HTTPS 服务端（交给 Caddy）
- ❌ 对外公网开放、注册、邮箱/短信验证
- ❌ OAuth2 / OIDC / SSO / LDAP 集成（后续可基于令牌机制扩展）
- ❌ 多租户、组织/角色复杂权限
- ❌ 密钥在线签名 / 双向 TLS 客户端证书
- ❌ 前端构建工具链（保持无构建步骤）
