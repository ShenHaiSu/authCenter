## 2. 安全验收检查清单逐项核验（对照文档 06 §11）

验收方式：真实验收 = 启动 `Bundle/windows/authcenter.exe`（发布产物）+ curl 全链路（10/10 通过）；代码层由既有单测/集成测试佐证。

| # | 检查项（06 §11） | 验证方式 | 结果 |
|---|------------------|----------|------|
| 1 | `CGO_ENABLED=0` 交叉编译两平台通过 | M5 构建脚本（build.ps1 步骤 4/5）产出 PE + ELF 产物，`go vet` 无告警 | ✅ |
| 2 | admin 初始化幂等（重启不重复生成密码） | 干净目录验收：首次打印 30 位密码 + auth.log 落盘一次；重启「admin 已存在，跳过初始化」，auth.log 不追加 | ✅ |
| 3 | 登录 5 次失败后锁定 15 分钟 | **真实验收**：先等 IP 限流窗口重置（61s）→ 连续 5 次错误密码（全部放行、失败计数达 5）→ 再等 IP 窗口重置（61s）→ 用**正确密码**仍返回 429（证明是用户名 15 分钟锁定而非 IP 限流） | ✅ |
| 4 | 认证失败按业务码区分（权衡后保留业务码便于排查） | 实测：错误密钥 10004/key_not_found、过期 10006/key_expired、指纹错 10007/fingerprint_mismatch、吊销 10005/key_disabled；集成测试覆盖 10001-10009 全分支 | ✅ |
| 5 | 日志/审计无明文密钥/密码（代码评审 + 抓日志验证） | **真实验收**：审计 14 条 detail 逐条比对 4 个密钥明文，泄露 0；stdout 日志无密钥明文；认证失败审计只记原因码 + 指纹（06 §4 允许记录指纹），不含提交密钥明文 | ✅ |
| 6 | 指纹绑定后错误指纹返回 fingerprint_mismatch 且写审计 | **真实验收**：错误指纹 → 10007；`auth.authenticate_failed` 审计落库（detail 含 fingerprint_mismatch）；正确指纹认证成功 | ✅ |
| 7 | 过期密钥返回 key_expired；吊销密钥即刻失效 | **真实验收**：`expires_at` 过去 → 10006/key_expired；`DELETE /keys/{id}`（软删 is_active=0，04 §3.5）后即刻 10005/key_disabled | ✅ |

> 附：会话/改密/登出、认证限流（每 IP 100 次/分钟）、密钥轮换宽限期等安全机制由 M2/M3 集成测试覆盖（TestSessionRequired / TestChangePassword / TestAuthenticateAPIRateLimit / TestKeyLifecycle），M6 复核无回归。

## 3. 性能冒烟（对照文档 08 §6）

环境：Windows 11 / Intel i7-9750H 2.60GHz / Go 1.26.5 / SQLite WAL（单连接）／ `go test -bench . -benchtime 1s`。

### 3.1 全量基准结果（M6 实测）

| Benchmark | M6 实测 | M1/M3 基线 | 说明 |
|-----------|---------|------------|------|
| BenchmarkAuthenticateSuccess | **1.85 ms/op** | 2.19 ms（M3） | 认证主路径（含审计写入 fsync） |
| BenchmarkAuthLookup | 37.4 µs/op | 45.8 µs（M1） | 认证核心 JOIN 查询 |
| BenchmarkKeyInsert | 1.75 ms/op | 1.87 ms（M1） | 密钥写入 |
| BenchmarkAuditInsert | 1.76 ms/op | 1.85 ms（M1） | 审计写入（含 fsync） |
| BenchmarkHealthz | 3.97 µs/op | 3.74 µs（M1） | HTTP 骨架 |
| BenchmarkUnknownAPI404 | 4.95 µs/op | 4.24 µs（M1） | 失败分支固定开销 |
| BenchmarkConfigParse | 3.60 µs/op | 4.77 µs（M1） | 启动配置解析 |
| BenchmarkArgon2Hash | 86.2 ms/op | 98.7 ms（M1） | argon2id（仅首次初始化一次性） |
| BenchmarkEnsureAdminFirstRun | 91.8 ms/op | 115 ms（M1） | 首次初始化完整成本 |
| BenchmarkEnsureAdminExisting | 15.9 µs/op | 55.9 µs（M1） | 幂等检查路径（每次启动执行） |
| BenchmarkRandomString30 | 297 ns/op | 337 ns（M1） | 30 位随机密码生成 |

### 3.2 性能预算分析（目标：认证接口 ≥100 QPS、P99 < 50ms）

```
认证主路径 1.85 ms → 单实例理论吞吐 ≈ 540 QPS（单连接串行）> 100 QPS 目标 5.4×
P99 远低于 50ms 预算（余量约 27×）
```

- 全部组件性能优于或持平 M1/M3 基线；审计写入（1.76ms）仍是主路径主要成本，高频场景可启用「审计异步化」预留策略（04 §7）。
- **结论：性能冒烟达标**，无优化紧迫性。
